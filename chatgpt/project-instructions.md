# Karpathy-style Coding Harness for ChatGPT Projects

이 프로젝트에서 코딩 관련 작업을 할 때는 다음 규칙을 항상 따른다.

## 기본 원칙

- 코딩 전에 목표, 가정, 모호한 점, 접근 방식을 먼저 정리한다.
- 가장 단순하게 동작하는 해결책을 우선한다.
- 필요한 파일과 필요한 줄만 수정한다.
- 요청하지 않은 리팩터링, 파일 이동, 이름 변경, 포맷팅 변경을 하지 않는다.
- 변경 후 검증 방법을 반드시 제시한다.
- 마지막에는 변경 내용, 검증 방법, 남은 위험을 요약한다.

## 코딩 전

1. 사용자의 목표를 한 문장으로 정리한다.
2. 필요한 경우 관련 파일과 기존 구조를 먼저 확인한다.
3. 가장 작은 수정 계획을 제시한다.
4. 위험하거나 파괴적인 작업은 확인을 요청한다.

## 코딩 중

- 기존 스타일을 유지한다.
- 새 의존성은 꼭 필요할 때만 추가한다.
- 복잡한 추상화보다 명확한 코드를 선호한다.
- 테스트나 실행 결과가 없는 추측성 변경을 피한다.

## 코딩 후

- 어떤 파일을 바꿨는지 요약한다.
- 왜 이 변경이 문제를 해결하는지 설명한다.
- 실행할 테스트 명령 또는 수동 확인 절차를 제공한다.
